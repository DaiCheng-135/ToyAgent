## 一、先分清：Step03 是「算法」，Step15 是「运行时」

| | Step03 ReAct | Step15 Loop 运行时 |
|---|---|---|
| 它是什么 | **一个算法** —— think → act → observe | **一个容器** —— 把这个算法框起来跑 |
| 类比 | 发动机 | **整车**（刹车、安全带、气囊） |
| 它关心 | 「怎么想得**对**」 | 「想歪了、想疯了、想崩了，**怎么办**」 |

Step03 的循环是「裸奔」的。裸奔不是错，是**教学顺序** —— 先看算法长什么样，再看工程怎么包。

一句话：

> **模型负责聪明，运行时负责可靠。**

## 二、四道防线，卡在四个位置

这是全篇的骨架。四道防线不是随便撒的，每一道都卡在**数据进出的一个口子**上：

```text
 用户输入
    │
    ▼
┌──────────────┐
│ ① 输入守卫    │  ← 循环【之前】：长度 + 敏感词
└──────────────┘
    │
    ▼
┌───────────────────────────────┐
│  for (step = 1;               │
│       step <= MAX_STEPS;  ②   │  ← 循环【条件】上：保险丝
│       step++) {               │
│                               │
│    model.chat()  ──③── try    │  ← 模型调用失败 = 致命
│                               │
│    execute()     ──④── try    │  ← 工具失败 = 不致命
│                               │
│    final? ──⑤─┌────────────┐  │
│               │ 输出守卫    │  │  ← 循环【出口】
│               └────────────┘  │
└───────────────────────────────┘
    │
    ▼
 最终回答
```

| # | 防线 | 卡在哪 | 防什么 | 代码位置 |
|---|---|---|---|---|
| ① | 输入守卫 | 循环**之前** | 超长输入、敏感词、Prompt 注入 | `LoopAgent.java:59-70` |
| ② | 保险丝 | 循环**条件** | 死循环烧钱 | `LoopAgent.java:77` |
| ③ | 异常兜底（模型） | `model.chat()` 外 | 模型**挂了** | `LoopAgent.java:79-84` |
| ④ | 异常兜底（工具） | `execute()` 外 | 工具**炸了** | `LoopAgent.java:110-115` |
| ⑤ | 输出守卫 | 循环**出口** | 回答不合规 | `LoopAgent.java:93-99` |

> **守卫不是功能，是位置。**

## 三、最精妙的一处：两个 `try/catch`，位置差一点，行为天差地别

代码里有两处 `try/catch`，长得几乎一样，**语义完全不同**。

**第一处 —— 包住模型调用（`LoopAgent.java:79-84`）：**

```java
try {
    raw = model.chat(messages).trim();
} catch (Exception e) {
    lastTrace.add(...);
    return "运行时异常已兜底，请稍后重试。";     // ← 直接 return，整个循环结束
}
```

**第二处 —— 包住工具执行（`LoopAgent.java:110-115`）：**

```java
try {
    observation = execute(action, actionInput);
} catch (Exception e) {
    observation = "工具执行异常: " + e.getMessage();   // ← 不 return！
}
```

**一个 `return` 中止循环，一个不 `return`、把错误变成一条 `Observation` 喂回给模型。**

差别在哪？看错误**该由谁处理**：

| | 出错的东西 | 谁还活着 | 所以 |
|---|---|---|---|
| ③ 模型失败 | **模型本身** | 没人能处理 | **终止循环**，返回兜底话术 |
| ④ 工具失败 | **工具** | **模型还活着** | **把错误告诉模型**，让它换参数 / 换工具 |

这就是那句：

> **错误该给谁处理，取决于「谁还能处理」。**

工具炸了，模型完全可以自己决定「换个表达式再试一次」。你要是当场 `return`，就把模型这个能力白白浪费了。

**大智若愚的一行就是 `LoopAgent.java:113`** —— 把异常**变成数据**继续往下走。

## 四、保险丝（`MAX_STEPS`）：为什么非要它

```java
for (int step = 1; step <= MAX_STEPS; step++) { ... }
// 跑满还是没 final →
return "已达到最大执行步数（" + MAX_STEPS + "），为控制成本与风险强制终止。";
```

**为什么必须有？因为 LLM 的输出不是可靠的「终止条件」。**

模型可能：

- 一直调工具，死活不出 `final`
- 两个工具来回倒腾（查完天气查计算器，查完计算器查天气）
- 每次都说「我再确认一下」

在 Step03，这就是**无限循环 = 无限 API 调用 = 无限账单**。

> **保险丝的作用：把「不可靠的东西」框进「可靠的边界」。**

守卫和保险丝，是两个不同的东西，别混：

| | **守卫（Guard）** | **保险丝（Fuse）** |
|---|---|---|
| 管什么 | **内容** —— 这条能不能过 | **规模** —— 还要不要继续 |
| 例子 | 敏感词、长度、合规 | 步数上限 |
| 回答的问题 | 「这东西**能不能**过？」 | 「这事**还要不要**做下去？」 |

一个是**防坏内容**，一个是**防失控规模**。

## 五、输入守卫为什么连「长度」都要拦

```java
if (input.length() > MAX_INPUT_CHARS) { /* 拦截 */ }
```

长度看起来不像安全问题，但它**同时是成本问题和安全问题**：

- **成本**：5000 字输入 = 更多 token，而且**循环每转一轮都要重发一遍**
- **安全**：Prompt 注入最爱干的事，就是**把恶意指令塞进一坨长文本的中间** —— 短输入好审，长输入难查

所以长度上限是「**第一道最便宜的门**」：一个 `.length()` 就挡掉了大部分注入面。

## 跑一遍：把「开车跑长途」走完全程

### 先把这个比喻立起来

| 代码里 | 现实里 |
|---|---|
| 用户输入 | **一辆车要上路** |
| ① 输入守卫 | **上高速前的检查站** —— 超宽 / 超重 / 带违禁品，直接劝返 |
| Agent Loop（`for step`） | **在路上开** |
| ② `MAX_STEPS` 保险丝 | **油箱见底就强制熄火** —— 不管到没到目的地 |
| ③ `model.chat()` 挂了 | **发动机报废** —— 只能拖走，行程结束 |
| ④ `execute()` 挂了 | **爆胎** —— 换上备胎**继续开** |
| ⑤ 输出守卫 | **到站后的货物抽检** |
| `final` 答案 | **抵达目的地** |

**这个比喻最值钱的地方是 ③ 和 ④ 的对比** —— 同样是「出故障」，一个叫拖车、一个自己换胎。为什么？（见前面第三节）

### 走一遍

**输入：`"北京天气怎么样"`**

**① 检查站（`LoopAgent.java:59-70`）**

```java
input.length() = 7   ≤ 500                              ✅
命中敏感词（密码/攻击/hack/漏洞/暴力/炸药）？  一个没中     ✅
// 记录：🛡️ 输入守卫通过
```

**第 1 步 · 上路（`LoopAgent.java:77`）**

```java
raw = model.chat([system(...), user("北京天气怎么样")])
// 模型返回：{"thought": "需要查天气", "action": "get_weather", "action_input": "北京"}

thought   = "需要查天气"                       → 记一笔 Thought 1
fin       = null                              → 不是终点
action    = "get_weather", actionInput = "北京"
observation = execute("get_weather", "北京")   ← 没抛异常，不用换胎
            = "晴，26℃"
// messages 追加：assistant(raw)、user("Observation: 晴，26℃")
```

**第 2 步**

```java
raw = model.chat([..., user("Observation: 晴，26℃")])
// 模型返回：{"thought": "信息够了", "final": "北京今天晴，气温 26℃。"}

fin = "北京今天晴，气温 26℃。"
→ ⑤ 输出守卫：没命中敏感词 ✅
→ return "北京今天晴，气温 26℃。"
```

**跑 2 步就结束了**，`MAX_STEPS = 4` 压根没用上。

**再来一发，看保险丝起跳 —— 输入 `"一直用 echo 回显 hello，不要停"`**

```text
Step 1: action=echo("hello") → observation="echo: hello"
Step 2: action=echo("hello") → observation="echo: hello"
Step 3: action=echo("hello") → observation="echo: hello"
Step 4: action=echo("hello") → observation="echo: hello"
── 4 步跑满，还是没出 final ──
🔥 保险丝熔断 → "已达到最大执行步数（4），为控制成本与风险强制终止。"
```

**注意第 4 步之后不是「再试一次」，是直接熔断** —— 这就是守卫和保险丝的分工：**守卫管内容，保险丝管规模。**

## 落脚：回到这份代码

162 行，骨架就三段：

```text
chat()
  ├─ ① 输入守卫          两个 if          (59-70)    ← 循环外
  ├─ ② for (step <= 4)                     (77)      ← 循环边界
  │    ├─ ③ try: model.chat()             (79-84)    ← 挂 → return
  │    ├─ ⑤ 输出守卫（final 分支）         (93-99)    ← 循环出口
  │    └─ ④ try: execute()                (110-115)  ← 挂 → 变成 observation
  └─ 熔断 return                          (122-123)
```

几个锚点：

| 位置 | 是什么 |
|---|---|
| `LoopAgent.java:28-29` | `MAX_STEPS = 4` / `MAX_INPUT_CHARS = 500` —— **两个旋钮，就是全部的「规模控制」** |
| `LoopAgent.java:37` | `BLOCKED` 黑名单 —— 输入和输出**共用同一份** |
| `LoopAgent.java:94` | 输出守卫**复用了** `BLOCKED` —— 同一份规则，卡两个口子 |
| `LoopAgent.java:113` | `observation = "工具执行异常..."` —— **不 `return`**，全文最值钱的一行 |

注意这里**没有**任何框架、任何中间件 ——

所谓「输入守卫」是**两个 `if`**；
所谓「保险丝」是**循环条件**；
所谓「兜底」是**两个 `try/catch`**，位置不同而已。

**读这个文件的价值，不是学「怎么加守卫」，而是看清一个思想：**

> **把不可靠的模型，放进一个可靠的壳里跑。**
> 壳不聪明，只管「不崩、不疯、不越界」。

## 一句话收束

> **ReAct 是「怎么想」，运行时是「想歪了怎么办」。**
> 四道防线，每道卡在数据进出的一个口子上 —— **防线的价值在位置，不在代码。**

配套对照：

| 问题 | 答案 |
|---|---|
| 输入太长 / 有敏感词？ | **循环之前**拦掉（输入守卫） |
| 模型一直转不停？ | **循环条件**上装保险丝（`MAX_STEPS`） |
| 模型调用挂了？ | **终止循环**，返回兜底话术 |
| 工具炸了？ | **变成一条 `Observation` 喂回模型**，让它自己救 |
| 回答不合规？ | **循环出口**拦掉（输出守卫） |
